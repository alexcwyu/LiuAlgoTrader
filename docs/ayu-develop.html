Purpose and scope

Scan symbols, distribute live market events to process-local async consumers, invoke strategies and broker adapters, and run direct historical replay with PostgreSQL trade/portfolio records.

Design decisions

Decision Rationale Tradeoff Evidence
Partition live events across consumer processes. Scanned symbols can run strategy workloads with process-local async loops. Queue ownership and broker selection are explicit; process parallelism is not cross-host distributed execution. main_cli (L32) / producer_async_main (L204)
Run historical replay directly rather than reproducing live queue processes. Backtest day loop calls scanners/strategies on historical timestamps with cached data. Historical timing/fills are a different path from asynchronous live broker/network queues. backtest_day (L346) / main_cli (L32)

Workflow

Live queued event to order

External broker/data/DB connectivity is required; this read-only audit performed no credentialed operation.

  W2["Reject stale/duplicate events, update bars, reconcile in-flight order."]
  W1 --> W2
  W3["Invoke per-symbol strategy.run with position/history."]

Strengths and limits

Strengths

  • Consumer handles existing in-flight orders before new strategy decisions and preserves symbol/time data provenance. handle_aggregate (L697) / handle_data_queue_msg (L727)

Limitations

  • Current validation retains credential-dependent failures; exclusion is completion policy, not evidence those broker paths operate live. docs/validation.md (L10)
  • Strategy schedule docstring says execution windows are not enforced; old architecture risk-table claim is inaccurate. Strategy (L24)
  • Selected Tradier factory branch caches TRADIER but reads TradierTrader key; this inspected inconsistency needs a focused code review and was not exercised or repaired. trader_factory (L13)
